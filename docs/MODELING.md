# 建模守則（建任何模型之前必讀）

店主定的（2026-11-13）：**建立或修改任何 3D 模型之前，先讀完這份**。三件事一起顧：**高品質、遊戲性、低面數**；並且**能用幾何形狀構成的，就用幾何形狀構成**。
低面數的各種做法（第六節）、貼圖怎麼畫（第七節）、試過不好的（第八節）也都在這份（原本分開的 `docs/LOWPOLY.md` 在第 1000 項併進來：建模的規則只留一個入口）；每件既有模型的紀錄在 `docs/DETAILS.md`（搜尋名字或檔名）。
照業界慣例整理、每條有門檻與檢查工具的標準（佈線、面數預算、UV 與貼圖、繪製、匯出、效能）在 [`docs/STANDARDS.md`](STANDARDS.md)；做完一件模型跑一次 `node scripts/topo-audit.mjs <檔案>`（新模型：扁三角 0、退化 0、極點 ≤ 10）。

## 一、三個原則

### 1. 高品質（近看要像真的）

- **先找參考**：店主給的照片、Sketchfab 預覽（只看圖，不下載）、真品的樣子。照參考的比例、配色、細節層次做，不憑印象。
- **貼圖要包得仔細**（店主說的：「貼圖包裝要仔細，才會好看」）。一張好貼圖有好幾層：
  - 底材：木紋、和紙纖維、草蓆的一列列、玻璃的厚薄與模具接縫。
  - 主體：大字、圖案，有大小對比。
  - 細節：小字欄、框線、印章、金箔點、英文拼音。
  - 舊化：磨損、污漬、邊緣壓暗。
- **字**：大字用毛筆字型 `blender/fonts/YujiBoku-Regular.ttf`（SIL OFL）；小字用 YuGothic。字一律畫進貼圖，不做成網格。
- **名稱**：酒名、商品名照真的命名方式自己創，上網查過沒有同名的真品才用（店主要的：不要亂取，也不要真的商標）。
- **假的立體會穿幫**：繩子、把手、凸起的邊這類有厚度、會被斜看的東西，用一點幾何讓它真的鼓起來，不只畫在平面上。菰樽的繩子就是先畫平的被店主指出，改成半圓的管子。

### 2. 遊戲性（放進店裡要能用、好用）

- **尺寸**：跟人物、吧台、行燈比例要對。放進遊戲前先量一件旁邊的東西當比例尺。
- **位置**：
  - 先量要放的地方（Box3、往下打射線看是哪個表面多高），留間距，不擋客人和員工的動線（`kitchenBlocks`、`paths.mjs`）。
  - 不擋客人看料理台的視線。
- **互動**：
  - 用 `<Movable id label>` 包起來，開發者模式能移動。
  - 名稱寫中文，日文、英文補在 `data/editText.ts`。
  - 要能指、能點的，給滑鼠提示（`setTip`）。合併過的模型沒有滑鼠事件，另外放一個看不見的感應方塊。
- **一眼認得**：從遊戲的一般視角（不只近拍）看得出是什麼。輪廓比細節重要。
- **會變的狀態**：例如烤熟變色、盤子變髒、庫存變少，改模型時要保留，改完實際跑一次流程確認。

### 3. 低面數（店主的鐵律，2026-11-02，不能改）

- **單一小物件 50～100 面**；圓的外圈 16～24 段（16 段輪廓會看出稜角時用 20）。造型複雜、要保住輪廓的才多一點。
- **不從中心放射收聚**（一圈三角形擠在一點，光影會出黑斑）：封口用 `blender/common.py` 的 `ladder_fill`（一格一格的梯狀四邊形）；`export_dish` 匯出前會把凸的多邊形封口自動轉成梯狀。
- **擺放先量邊界，不准穿模、不准兩個面在同一平面**：量 Box3／`bound_box` 留間距；貼在表面的東西抬高幾公釐或 `polygonOffset`。
- **字不做成網格**：畫進貼圖。
- 做法由便宜到貴的選法（一片貼圖、十字薄片、方塊加貼圖、假透視平面、低模加畫的貼圖、烘焙），見第六節。

## 二、能用幾何就用幾何

形體先用**簡單的幾何形狀組出來**，細節才交給貼圖：

| 形體 | 用什麼幾何 | 例子 |
|---|---|---|
| 圓的、轉出來的 | 車削（一條輪廓繞一圈，16～24 段，幾圈就夠） | 酒瓶、菰樽的桶身、花瓶、碗 |
| 有斷面的長條 | 擠出（一個 2D 斷面沿直線拉長） | 兩層的酒台、木框、門檻 |
| 方的 | 方塊（需要時倒一刀角） | 箱子、台座、腳 |
| 沿線走的 | 管子（4～6 邊；只看得到一半的用半圓 3 面） | 繩子、把手、電線 |
| 薄的、細碎的 | 一片或十字交叉的薄片＋透明貼圖 | 稻草末端、葉子、吊牌 |

原則：

- **輪廓用幾何，表面用貼圖**。輪廓（剪影、厚度、凸起）是幾何的事；顏色、紋路、字、小凹凸（法線貼圖）是貼圖的事。
- **組件少而準**：每個零件都要說得出存在的理由（輪廓、厚度、會動、會被點）。看不出差別的零件不要。
- 減面工具是最後手段：先想能不能從源頭用幾何重做（店主看過減面工具弄壞的惠比壽）。

## 三、流程（每一件都照做）

1. **讀**：這份（含第六～八節）；在 `docs/DETAILS.md` 搜尋它或它旁邊的東西。
2. **參考與計畫**：
   - 列出參考、形體由哪些幾何組成、面數預算、貼圖張數與內容、放在哪裡（檔案：行號、量到的座標）。
   - 重大的先給店主看。
3. **建**：`blender/<名字>.py` → `public/models/<名字>.glb`；印出三角面數（例：`KOMODARU_TRIS`）；輸出 Blender 預覽圖。
4. **放進遊戲**：材質照第七節的設定（toon、透明薄片、法線貼圖保留、需要反光的用 standard 加 `reflectStudio`）；預設位置寫進 `edit.ts`。
5. **檢查**：
   - `node scripts/mesh-audit.mjs <模型>`、`node scripts/topo-audit.mjs <模型>`、`node tests/e2e/clips.mjs`。
   - 遊戲裡同一鏡頭近拍與一般視角各一張；改舊模型要前後對照：舊模型用 `git show HEAD:public/models/x.glb` 存成暫存檔，Playwright 的 `page.route` 換回來拍（需要舊程式時，暫時把 `git show HEAD:` 的那個 .tsx 換回去拍完再換回來，一律先寫暫存檔再 `mv`）。看得出變差就再改，不要交出去。
   - 量三角面與繪製次數的前後。
   - `npx tsc -b`、`npm test`；動到流程的跑 `npm run e2e`。
6. **記錄**：
   - `TASKS.md` 那一列寫結果與數字：面數前後、檔案大小前後、場景總面數與繪製次數前後、對照圖的路徑；`WORKLOG.md` 寫過程與試錯。
   - `docs/DETAILS.md` 寫做法與店主為什麼要這樣。

## 四、店主說過的（不要再犯）

- 貼圖太陽春、色塊加字就交：要有層次（見「高品質」）。
- 畫上去的繩子、繩圈被看出是平的：給一點幾何。
- 亂取酒名（例：把店名「聞野」當酒名）、用真的牌子（例：菊正宗）：都不行，照真品的命名方式自創並查過。
- 面數太多的地方：串上的切身、椅子、喇叭、碗盤櫃裡的杯碗、保溫桶。都改成幾何加貼圖（第 74～81 項）。

## 五、造型感（第 379 項，店主 2026-11-19：「覺得跟overcooked 2的風格還是有落差，造型感上」）

那類卡通料理遊戲共通的感覺（不照抄那款遊戲的角色與美術，是自己的日式燒烤店）：**形體厚實、輪廓好認、色塊清楚、動起來有彈性**。跟「高品質」不衝突：形體負責遠看的份量，細節與層次照樣畫在貼圖裡（第一個示範：酒台，第 380 項）。

- **輪廓先行**：從遊戲的一般視角（總覽、灶台）一眼看得出是什麼、份量夠。板子比真的厚一點，邊緣倒大圓角，不做細薄的片。
  - 用 `blender/common.py` 的 `chunky_box`：倒角修改器加硬化法線，平面照樣平、圓角是滑的（不是一格格的折面），套用後再依材質合併（合併前沒套用，倒角會丟掉）。
- **比例稍微誇張**：主角級、會一直被看到的擺設稍微放大、加厚；把手、提把、蓋鈕這些手會碰的地方做大一點。
- **色塊清楚**：主色飽和、彼此對比分明（例：朱漆、黑漆、金）。舊化與細紋畫在貼圖裡，但不能把大色塊弄髒，遠看要乾淨。
  - 有光澤的漆、金屬用 standard 加 `reflectStudio`；鮮豔的顏色斜看會被環境反光洗白（酒台的朱漆曾經變成珊瑚粉），環境反光要調弱。
- **兩面都要好看**：店中間的擺設，客人那側與老闆、員工那側都會被看到（酒台：正面「銘酒」、背面「聞野」）。
- **情緒與回饋用貼紙圖示**：厚白邊、深色細線、飽和色，畫成形狀，不用字元（`scene/people/crewEmote.ts`，第 381 項）。
- **動起來要有彈性**：預備、擠壓伸展、過衝、餘勢（圖示彈出會過衝再回來；員工開心時走路有彈跳、累了垮肩）。
- **每改一件**：總覽與灶台視角各拍前後，再加近拍；面數、繪製次數、著色程式前後都要量。

## 六、低面數的做法：由便宜到貴

店主的方向：**乾淨的低面數形體（四邊形為主），細節全部進貼圖**（顏色、法線），不是很多面，也不是減面工具減出來的碎三角形。看得到的東西照「離鏡頭多近、從幾個角度看」挑最便宜的一種：

| 做法 | 幾面 | 什麼時候用 | 例子 |
|---|---|---|---|
| **一片貼圖**（四邊形 2 面，透明處用 alpha 切掉） | 2 | 只從前面看、或藏在櫃子裡、層架後排的東西 | 飲料櫃後排、碗盤櫃裡的碗疊（第 74 項）、遠處的瓶子 |
| **拍原本的樣子貼在一片上**（在 Blender 用正交相機拍原本的模型，背景透明，拼進一張圖） | 2～4 | 收在櫃子、抽屜裡，只從一兩個方向看的一疊東西 | 碗盤櫃的碗疊與湯匙（第 74 項：3,020 → 28 面） |
| **十字交叉薄片**（2～3 片，雙面、alphaTest） | 4～6 | 細碎的植物、毛邊、繩頭，從各角度都要有點厚度 | 柳樹葉、神棚供花（第 57 項）、菰樽的稻草末端（第 72 項） |
| **方塊／盒子＋貼圖**（四面或六面都貼圖） | 10～12 | 方的東西、或一整排並排的東西，從斜角也要看得出厚度 | 紙箱、酒箱裡的一排瓶子（瓶的輪廓畫在側面，透明切掉） |
| **假透視的平面**（一片，著色程式算視線穿進去碰到哪裡） | 2 | 門裡、窗外的空間：要有深度，又不想做出整個空間 | 上二樓的樓梯（見下面）、圓窗外的景色 |
| **低面數形體＋畫的貼圖＋法線貼圖** | 50～1,000 | 主角級的擺設，近看要有體積 | 菰樽（第 72 項）、小判、地瓜馬鈴薯 |
| **高模烘焙到低模**（顏色、法線、AO） | 依造型 | 雕刻感的東西，形狀複雜但輪廓簡單 | 招財貓、惠比壽（第 59 項）、地瓜（`bake_tubers`） |

### 假透視的平面怎麼做（上二樓的樓梯）

`dining/staffDoor.tsx` 的 `STAFF_STAIRS`（員工門後面）：門框裡只有**一片兩個三角形的平面**，自己的 `ShaderMaterial`。每個像素：

1. 從鏡頭的位置（`uCam`，換成這片平面自己的座標）拉一條線，穿過這個像素，往牆後面延伸。
2. 用數學算這條線先碰到樓梯間的哪個面：左右的牆、入口的地板、每一階的踏板與踢板（`stairY`：在這個深度第幾階、多高）、斜的天花板、平台後面的牆。
3. 照碰到的那個面上色：杉木腰板、灰泥、木紋；平台上紙燈的暖光、門口照進來的一點光；角落與階梯的折線壓暗，跟門框接的邊最暗。

所以從任何角度看，樓梯都在門後面「有深度」地往上，視差是對的（畫死的一張圖只有正面看才對），卻只花 2 個三角形、一次繪製。圓窗外的景色是同一個原理（多層圖疊出前後）。限制：只適合**看進去、不會走進去**的空間；形狀要能用簡單的數學描述（平面、盒子、階梯）。

## 七、貼圖怎麼畫

- 用 numpy 在 Blender 腳本裡畫（`common.py` 的 `fbm`、`smooth`、`mix`、`grid01`、`image`）；高度圖轉法線用 `to_normal`，遊戲裡要保留 `normalMap`（toon 材質也可以）。
- **字**：Blender 文字物件轉三角形，填進貼圖（2～4× 超取樣）。平面的用 `DecalAtlas`；曲面上的直接畫進那個面的貼圖（菰樽的 `Print`）。這台電腦只有 YuGothic，要粗的毛筆感用擴張（菰樽的 `brush`）。
- 一組相同的東西共用一張圖、一格一個（三個菰樽一張 2048×1536、一列一個），一個材質就一次繪製。
- 透明薄片的貼圖在遊戲裡：`alphaTest 0.5`、`DoubleSide`、**不做縮圖**（遠看細的東西才不會變禿）、不描線（`inkModel` 第二個參數跳過，不然整片的邊被描黑）、通常不投影。
- 不用 `transmission`（玻璃瓶用一般材質加畫的反光）。

## 八、試過不好的

- 減面工具（`blender/optimize_glb.py`）對有烘焙 UV 的模型會弄亂（惠比壽一片黑色碎片）；繩子會變扁、桶身出現接縫（舊的菰樽）。能從源頭重做就重做。
- 一堆一顆顆的東西（馬鈴薯堆）整堆烘到一個殼上：輪廓與縫不見了，像一塊麵包。要留真的一顆顆，或改用薄片。
- 平面畫死的一張景深圖：只有正面看才對（樓梯第一版），要有深度用假透視的平面。
